# 从校园邮箱到可交付工作，Postbird 的一次技能化整理

这份稿件依据仓库现有代码与文档撰写。发布前请团队补入真实开发经历、日期、成员分工和演示结果，删除与实际不符的内容。

校园工作里最麻烦的邮件，往往并不是最长的那封。它可能只有几行字，却把截止时间放在正文、格式要求放在附件、补充说明放在后续回复中。办奖学金评审、组织活动报名、跟进导师修改意见，都要把这些碎片重新拼成一件可执行的事。

Postbird 想解决的就是这一段距离。它先用只读方式建立邮件索引，再从主题、摘要和线程里提取行动与日期。需要深查时再读完整邮件或本地附件，并把依据指回原邮件、PDF 页、Word 段落、PPT 页或表格行。接着，它可以整理材料台账、生成回复草稿，输出 Excel、Word 和 PPT。发邮件是另一道门，必须先预览，再由人明确确认。

这次整理参赛版本时，我们把已有的 22 个模型工具梳理成一份 Agent Skill。`SKILL.md` 告诉 Agent：遇到今日待办先走简报和行动雷达，遇到材料收集走台账，遇到附件问题保留引用，遇到发送要求先停在预览。这是一层任务路由和操作边界，不是凭空增加一个模型。我们也保留了静态 Live Demo，让没有邮箱授权的人可以先用模拟数据看清工作流。

本地示例可以不连接邮箱，执行 `npm run demo` 后检查生成的表格、通知文档和演示文稿。真实邮箱接入需要用户自己的授权码，并由其在本地配置。这样的分层让演示更容易复现，也让公开仓库不必包含真实邮件。

目前的边界同样清楚：仓库还没有 NVIDIA SDK、NVIDIA 模型或 StepFun 的已验证调用，也没有 DGX Spark 上的性能记录。下一步如果进入这些平台适配工作，我们会保留实际的运行命令、模型版本和结果，再讨论它带来了什么收益。参赛展示可以先从一条被遗漏的校园通知开始，让评委看到它如何一步步变成有依据的行动和可交付文件。
