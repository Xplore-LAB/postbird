# Postbird 黑客松项目报告书

## 一句话介绍

Postbird 把校园邮箱中分散的通知、线程和附件变成可核查的行动清单、回复草稿、材料台账和真实 Office 文件。使用者可以从一句自然语言请求出发，完成“找要求—追截止—核材料—出文件”的工作流。

## 场景与价值

辅导员收集奖学金材料、学生组织处理活动报名、研究生追踪导师的修改要求，都会面对同一个问题：要求散落在邮件正文和附件中，截止日期容易遗漏，回复和统计又需要重复劳动。Postbird 面向这些具体场景提供七类身份入口。项目的价值主张是减少人工整理和漏项，同时把每个结论连回原始邮件或附件位置，便于复核。当前仓库没有公开的节时或准确率对照实验，因此不宣称已量化提升。

## 技术方案与 Agent Skills

现有应用是 DeepSeek Harness 插件，使用 Node.js 20+，通过 `lib/index.js` 注册 22 个模型可调用工具。收件模块用只读 IMAP 建立本地索引；`lib/workflow.js` 从索引提取截止日期、行动信号、线程摘要与回复上下文；附件模块读取 PDF、Word、PPT、Excel 和文本；Office 模块输出 CSV、XLSX、DOCX、PPTX 等文件。`SKILL.md` 是本次补充的 Agent Skill，描述何时调用哪组工具、怎样保留证据、以及发件必须经过预览和明确确认。它复用现有工具，不把一个说明文件冒充新的多智能体系统。

```text
自然语言请求 → Postbird Skill 路由 → DSH Agent 调用 office_* 工具
                  ↓
只读邮件索引 / 本地附件 → 行动雷达、材料台账、回复草稿
                  ↓
人工复核 → Office 文件或邮件预览 → 明确确认后才可发送
```

## 完整性、部署与演示

在 Node.js 20+ 环境中克隆仓库，运行 `npm run setup` 安装并注册 DSH 插件，再运行 `npm run doctor` 检查。真实邮箱是可选配置，授权码通过环境变量提供。`npm run demo` 是无邮箱的本地 Office 示例，能输出表格、通知文档和演示文稿。GitHub Pages 的 Live Demo 仅使用模拟数据，适合展示七类校园身份与交互流程。完整部署步骤和限制见主 [README](../README.md)。

## 平台适配说明

Postbird 当前代码不含已验证的 NVIDIA SDK、NVIDIA 模型或 StepFun 调用，也没有 DGX Spark 上的运行基准。若比赛要求这些能力，应在参赛环境中实际接入、测试并记录命令、模型版本和结果后再写入报告。本版只陈述已在仓库中可查的 DSH/Node.js 实现，不将通用 Node.js 可运行性等同于 DGX Spark 适配验证。

## 安全与复现边界

IMAP 读取保持只读，数据路径限制在工作目录；发件采用预览 ID 与 `confirm:true` 的两阶段流程。不要把真实邮件、个人信息、授权码或敏感附件上传到公开演示。静态 Demo 的样例文件与真实邮箱无关。评审可以先看 Live Demo，再按 README 在自己的 DSH 环境执行本地示例。项目没有在本仓库实现视频录制、B 站发布或赛事征文发布。
