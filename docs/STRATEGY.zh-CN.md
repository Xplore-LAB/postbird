# Postbird 对外传播与增长策略

> 更新日期：2026-09-07
>
> 当前产品事实：v1.7.0，22 个模型工具，140 项端到端检查，插件自带 4 个 DSH 技能，七类校园身份在线 Demo。

## 一、对外定位

### 首屏主张

> **Postbird 信鸽**
>
> 把校园邮箱变成会行动的 AI 工作台。
>
> 一句话整理通知、追踪截止日期、汇总材料、起草回复，并交付真实的 Word、Excel、PPT 和邮件文件。

### 用户心智

Postbird 的核心词是“校园邮箱行动中枢”。公开内容持续强化四个印象：

1. 一句话启动，无需理解工具名。
2. 从阅读邮件继续走到完成工作。
3. 每项结果都能回到邮件或附件依据。
4. 索引与文件本地保存，发送由用户确认。

## 二、从 MiroFish 学到的展示方法

[MiroFish 的公开 README](https://github.com/666ghj/MiroFish)把复杂能力压缩成清晰首屏：独特视觉标识、短定位、可信度信号、双语入口、Overview、输入与输出、愿景、演示和部署。这种结构让访客先理解价值，再决定是否安装。

Postbird 已将相同的信息效率应用到自己的产品表达：

| 展示位置 | Postbird 的做法 |
| --- | --- |
| 品牌视觉 | 镜面信鸽主视觉与独立字标 |
| 一句话定位 | 把校园邮箱变成会行动的 AI 工作台 |
| 首屏行动 | 在线体验、校园场景、五分钟开始 |
| 可信度 | 版本、22 个工具、135 项检查、本地优先、MIT |
| 输入与输出 | 用户说一句话，Postbird 返回行动、证据与真实文件 |
| 具体体验 | 七类校园身份和九类核心工作流 |
| 安装信息 | 放在价值与效果之后，并将邮箱配置折叠 |

借鉴限于信息架构与展示节奏。Postbird 的场景、文案、交互、视觉和技术实现保持原创。

## 三、校园痛点依据

高校沟通资料反复出现三类需求：

1. 学生收到大量重复、模糊或低优先级邮件，重要的资助、注册和学业通知可能被遗漏。[USC PASS 关于高校邮件过载的研究摘要](https://pass.pullias.usc.edu/news/email-overload-rethinking-university-communication-with-at-promise-students/)强调邮件应简洁、结构清楚并明确行动。
2. 研究生与导师需要明确沟通方式、里程碑、截止日期和下一步，并用书面记录确认共识。[Cornell 研究生指导指南](https://gradschool.cornell.edu/academic-progress/opportunities-resources-support/advising-guide-for-professional-students/)建议在沟通后用邮件记录理解、约定和下一步。
3. 学生给教师的邮件需要专业、简洁和具体，长邮件容易延后处理。[Stanford 的教师邮件指南](https://advising.stanford.edu/current-students/advising-student-handbook/email-faculty)强调礼貌、明确主题、简短具体和及时跟进。
4. 学生社团活动从策划开始就要准备审批表、预算、安全预案、场地与宣传材料，活动结束后还要处理决算、宣传总结和归档。[西南大学学生社团活动申请](https://jgdw.swu.edu.cn/info/1151/5231.htm)与[中国石油大学（北京）学生社团活动经费细则](https://www.cup.edu.cn/tuanwei/202606xg/szyxxt/stjszdb/dcb68c41e725455ca23bb4dfb3960670.htm)展示了这条完整材料链。
5. 竞赛与作品征集常要求报名表、承诺书、作品、缴费截图、实名与匿名版本，并规定文件命名和统一汇总方式。[北京交通大学大学生交通科技大赛通知](https://bjctrans.bjtu.edu.cn/zxdt/tzgg/7ddc81d7fb9d4f93addc1e3482e81f2f.htm)与[华中师范大学大广赛征集通知](https://jc.ccnu.edu.cn/info/1065/6153.htm)体现了高频的缺件、错版和命名核对任务。

这些需求直接映射到 Postbird 的每日简报、行动提取、线程摘要、上下文回复与材料追踪。

## 四、七类身份的传播钩子

| 身份 | 最有传播力的一句话 | 展示结果 |
| --- | --- | --- |
| 本科生 | 61 封通知变成 4 项本周必做 | 行动清单和截止日期 |
| 研究生 | 导师一封邮件变成论文修改计划 | 线程依据、附件位置和回复 |
| 辅导员 | 86 名学生的材料一句话核对 | 缺件名单、提醒预览和 Excel |
| 行政老师 | 128 封报名邮件一次交付 | 名单、提醒、Word 和 PPT |
| 教学老师 | 课程邮箱直接显示班级状态 | 作业、补交、请假和统一回复 |
| 教授 | 最近三天只留下 5 件决策 | 论文、合作、审批和委派事项 |
| 学生组织 | 126 封活动邮件变成一张行动台 | 报名、缺件、重复提交、审批与交接目录 |

第一阶段传播重点为研究生、辅导员、行政老师和学生组织。这些工作线程更长、附件更多、交付链条更完整，适合展示 Postbird 的综合能力。学生组织还具备高频传播、多人协作和换届复用价值。

## 五、内容与渠道

### GitHub

README 首屏负责完成三件事：让访客理解产品、点击 Demo、找到五分钟开始。Issues 收集真实场景，Discussions 用于发布校园工作流配方。

### 内容平台

优先制作可复现的结果型内容：

1. 《导师 6 封修改邮件，如何在一分钟内变成论文计划》
2. 《辅导员如何核对 86 名学生的奖学金材料》
3. 《128 封培训报名邮件，如何一次生成 Excel、Word 和 PPT》
4. 《你的邮箱里到底藏了多少截止日期》
5. 《为什么邮件 AI 的每个结论都应该带出处》
6. 《126 封社团报名邮件，如何变成缺件清单和活动推进表》
7. 《一场校园活动，从策划审批到报销归档要收齐哪些材料》

每篇内容采用相同结构：真实痛点、用户一句话、处理过程、可下载结果、安全边界、在线 Demo 链接。

### 校园冷启动

1. 邀请研究生、辅导员、行政老师和学生组织负责人各 3 至 5 人完成任务测试。
2. 收集完成耗时、人工步骤数、漏项数和复核次数。
3. 将脱敏后的结果制作成 Demo 数据和案例文章。
4. 优先修复影响首次成功的配置与识别问题。

## 六、发布内容规范

1. 使用具体数字、真实文件和可点击 Demo 证明能力。
2. 所有宣传结果与当前版本、代码和测试保持一致。
3. 对自动识别准确率保持克制，明确人工复核位置。
4. 不使用无法验证的“全自动”“零错误”“最安全”等绝对表述。
5. 不展示真实学生、教师、邮箱地址或敏感材料。
6. 不自动发送催办或回复，演示中持续显示发送确认边界。

## 七、产品指标

| 阶段 | 建议指标 |
| --- | --- |
| 首屏理解 | 访客能否在 30 秒内说出产品解决什么问题 |
| Demo 激活 | 进入页面后选择身份并运行一次的比例 |
| 结果信任 | 点击“查看依据”或下载结果的比例 |
| 安装成功 | 从 README 进入 setup 并通过 doctor 的比例 |
| 首次价值 | 用户首次完成真实邮件或文件工作流的时间 |
| 持续使用 | 一周内再次运行每日简报、材料追踪或回复流程的比例 |
